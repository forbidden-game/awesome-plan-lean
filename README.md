# Awesome Plan Lean

适用于不同项目的轻量级 AI 编程 Agent skill：保留目标、工作流、约束和长期记忆，减少重复台账与流程维护。

完整且独立的技能规范是 [awesome-plan.md](awesome-plan.md)。只需加载这一份，不需要读取其他版本。

## 一句话开始使用

在目标项目中，把下面这句话发给能够读取网页和操作仓库的 Agent：

```text
请读取并采用 https://raw.githubusercontent.com/forbidden-game/awesome-plan-lean/main/awesome-plan.md 中的 Awesome Plan Lean skill：先检查当前项目，按 skill 确认项目模型、既有规范和补充约束后部署；远端修改前确认 GitHub 或 local-only 模式，未经我单独批准具体 Queue 不得开始实现。
```

Agent 会先检查项目、复用已有事实和计划，只询问缺失的关键决策，然后呈现模型供你确认。**采用 skill、同意目标或确定优先级，都不等于批准实现。**

首次采用时，将选定的 skill 保存到目标项目，在已有 `AGENTS.md` 或等价入口中登记技能文件与项目记录的位置；不要覆盖原有指令。后续会话使用项目选定的本地版本，不自动切换到最新发布。

`main` 链接随发布更新。需要可复现采用时，将 URL 中的 `main` 换成已审阅的提交 SHA。Agent 无法联网时，可以手动下载同一文件后使用。

## 保留什么，简化什么

- 保留最终目标、范围、Milestone Goals、Workstreams、当前焦点与 Guardrails。
- 每个事实只在一个权威位置维护，其他地方链接引用；不要求每个层级都创建文件或 Issue。
- Phase 按需使用；规范检查并入交付验收，不默认增设独立审计阶段。
- 复用项目已有规范与工具配置，不额外维护重复的标准副本。
- 具体 Queue 明确范围、验收、依赖与批准；范围内技术选择和正常修错不反复审批。
- 用真实验证支持完成声明；保留重要决策、历史结果、阻塞与恢复条件。

默认只维护两个当前记录，历史有真实结果后再追加。已有等价记录时直接复用，不为文件名另建系统：

| 记录 | 职责 |
| --- | --- |
| `plan/project.md` | 目标、范围、里程碑、Workstream、Guardrails、长期决策与工作约定 |
| `plan/current.md` | 当前焦点、具体 Queue、批准、执行状态、阻塞、恢复点与待发布事项 |
| `plan/history.md` | 已结束尝试的范围、结果、证据、决策与残余工作 |

## 本地或 GitHub

**local-only：** 项目文件是权威记录，不依赖 GitHub，也不承担远端同步流程。

**GitHub：** 新部署默认以项目文件为权威记录，按约定发布链接和 Queue 级摘要，不自动创建整套 Boards、字段和关系。已有 GitHub 原生项目保留其权威记录与已验证集成；切换归属需要明确同意。

这是供 Agent 执行的工作约定，不是后台同步服务，不宣称提供多写入者并发安全或完整离线冲突处理。

## 使用边界

先审阅 skill，再授权 Agent 在项目中采用。项目指令和更高优先级规则仍然有效；工具可用、账号已登录或计划已存在都不是额外授权。

执行只限已批准的 Queue。发现范围外问题可以记录，但不能顺手扩展实现；一个 Queue 结束后，不自动开始下一个。
